This guide builds a grid that a screen reader announces as "item 4,200 of 10,000", and that keyboard users can move through with the arrow keys.

A list of 10,000 items keeps only a few hundred of them in the DOM, so a screen reader that counts elements reports a few hundred. The grid does not add ARIA roles or focus handling. Instead, it gives you each item's index and the primitives to compute its row and column, so you can build both yourself.

::steps
### Add list roles

The samples in this guide use a list of 10,000 items held in memory.

```vue
<script setup lang="ts">
import { createPageProvider } from "vvirtual-grid/vue";

const items = Array.from({ length: 10000 }, (_, i) => ({ title: `Item ${i + 1}` }));
const pageProvider = createPageProvider(items);
</script>
```

Add `role="list"` to `<VirtualGrid>`, and `role="listitem"` to the root element of both slots.

```vue
<template>
  <div class="h-96 overflow-y-auto">
    <VirtualGrid
      role="list"
      :length="items.length"
      :page-size="40"
      :page-provider="pageProvider"
    >
      <template #default="{ item, index, style }">
        <div :style="style" :data-index="index" role="listitem">
          {{ item.title }}
        </div>
      </template>

      <template #placeholder="{ index, style }">
        <div :style="style" :data-index="index" role="listitem" />
      </template>
    </VirtualGrid>
  </div>
</template>
```

The scroll container is the `div`. Do not set `overflow` or a height on `<VirtualGrid>` itself.

### Set the size and position of each item

Add `aria-setsize` with the total length and `aria-posinset` with the item's position to the root element of both slots. `aria-posinset` counts from 1 and `index` counts from 0, so add 1.

```vue
<template #default="{ item, index, style }">
  <div
    :style="style"
    :data-index="index"
    role="listitem"
    :aria-setsize="items.length"
    :aria-posinset="index + 1"
  >
    {{ item.title }}
  </div>
</template>
```

Add the same two attributes to the root element of the `placeholder` slot.

A screen reader now announces the item at index 4199 as position 4,200 of 10,000, although only a few hundred items exist in the DOM. The exact wording varies by screen reader and browser. See [ARIA examples](/examples/aria) for a runnable version.

### Mark placeholders as busy

Add `aria-busy="true"` to the placeholder slot's root element. A placeholder has no content yet, and `aria-busy` tells the screen reader the content is still loading.

```vue
<template #placeholder="{ index, style }">
  <div
    :style="style"
    :data-index="index"
    role="listitem"
    aria-busy="true"
    :aria-setsize="items.length"
    :aria-posinset="index + 1"
  />
</template>
```

### Keep the focused index in a ref

Store the index of the focused item in a ref, not the focused element. Items leave the DOM when the user scrolls away, so an element you stored would be removed.

Give `tabindex="0"` to the item whose index equals the ref, and `tabindex="-1"` to every other item. This pattern is called a roving tabindex. The Tab key reaches the one item with `tabindex="0"`, and your code moves the focus between items.

Add the two refs to the script from the first step, `ref="grid"` to `<VirtualGrid>`, and the `tabindex` to the default slot. The placeholder slot stays as before.

```vue
<script setup lang="ts">
import { ref, useTemplateRef } from "vue";

const grid = useTemplateRef("grid");
const focused = ref(0);
</script>

<template #default="{ item, index, style }">
  <div
    :style="style"
    :data-index="index"
    role="listitem"
    :tabindex="index === focused ? 0 : -1"
    :aria-setsize="items.length"
    :aria-posinset="index + 1"
  >
    {{ item.title }}
  </div>
</template>
```

### Listen for arrow keys on the grid

Add `@keydown="onKeydown"` to `<VirtualGrid>`. Key events bubble up from the focused item, so one listener on the grid receives them all.

Map each arrow key to a change of row or column. Convert the focused index to a cell with `getItemCell`, change the cell, and convert it back with `getIndexByCell`. Both read a reusable query object, so create it once outside the handler.

:::code-collapse
```ts
import { createCellQuery, getIndexByCell, getItemCell } from "vvirtual-grid/primitives";

const cellQuery = createCellQuery();

function onKeydown(event: KeyboardEvent) {
  const layout = grid.value?.measurement;
  if (!layout) return;

  cellQuery.layout = layout;
  cellQuery.index = focused.value;
  getItemCell(cellQuery);

  const { cell } = cellQuery;
  if (event.key === "ArrowDown") cell.row += 1;
  else if (event.key === "ArrowUp") cell.row -= 1;
  else if (event.key === "ArrowRight") cell.column += 1;
  else if (event.key === "ArrowLeft") cell.column -= 1;
  else return;

  if (cell.row < 0 || cell.column < 0 || cell.column >= layout.columns) return;
  const next = getIndexByCell(cellQuery);
  if (next < 0 || next >= items.length) return;

  event.preventDefault();
  moveTo(next);
}
```
:::

The checks before `getIndexByCell` stop the focus at the first row, the first and last column, and the end of the list.

::warning
The check `cell.column >= layout.columns` is correct only for the default `grid-auto-flow: row`. With `grid-auto-flow: column` the items fill a fixed number of rows and the columns grow with the list. Replace it with `cell.row >= layout.rows` there, or read `layout.flow` and pick the check that matches.
::

### Scroll to the new item and focus it

Set the grid's `scrollTo` prop to the new index. The grid scrolls there and renders the item. The item may not exist in the DOM until then, so focus it once it does.

Add `:scroll-to="focused"` and `scroll-behavior="auto"` to `<VirtualGrid>`, and `@render="focusFocused"` to run after the grid patches the DOM. When the new item is already rendered, the grid may not emit `render`, so `moveTo` also tries to focus it at once.

`pendingFocus` is true from the key press until the item has focus. Without it, `focusFocused` would also run when the user scrolls with the mouse, and pull the focus into the grid.

```ts
import { nextTick } from "vue";

let pendingFocus = false;

function moveTo(index: number) {
  focused.value = index;
  pendingFocus = true;
  nextTick(focusFocused);
}

function focusFocused() {
  if (!pendingFocus) return;
  const element = grid.value?.$el.querySelector<HTMLElement>(
    `:scope > [data-index="${focused.value}"]`,
  );
  element?.focus({ preventScroll: true });
  if (element && document.activeElement === element) pendingFocus = false;
}
```

```vue
<template>
  <div class="h-96 overflow-y-auto">
    <VirtualGrid
      ref="grid"
      role="list"
      :length="items.length"
      :page-size="40"
      :page-provider="pageProvider"
      :scroll-to="focused"
      scroll-behavior="auto"
      @keydown="onKeydown"
      @render="focusFocused"
    >
      <!-- slots from the earlier steps -->
    </VirtualGrid>
  </div>
</template>
```

`preventScroll` stops the browser from scrolling the item into view a second time, because `scrollTo` already did.

### Check it with a screen reader

Open the page with VoiceOver on macOS (Cmd + F5) or NVDA on Windows.

1. Press Tab until the focus reaches the grid. The screen reader announces the first item with its role and its position, 1 of 10,000.
2. Press the arrow keys. Each press moves the focus to the next item in that direction and the screen reader reads it.
3. Press the down arrow many times. The grid scrolls, and the announced position keeps counting up, for example 4,200 of 10,000.

The wording and the order of the announcement vary by screen reader and browser. [ARIA examples](/examples/aria) has runnable versions of each step and instructions for testing without a screen reader.
::

::warning
Do not point `aria-activedescendant` at an item in the grid. The element is removed when the item scrolls out of the rendered window, and the reference then points at nothing. Move real focus with a roving `tabindex` as above.
::

::note
If the user scrolls with the mouse until the focused item leaves the DOM, no item has `tabindex="0"` and Tab cannot enter the grid. Scrolling back to the focused item restores it.
::

## Choosing a role pattern

The `list` and `listitem` roles used above work because the grid renders its items as flat children of one element, and a list needs exactly that. The `listbox` and `option` roles fit for the same reason. Use them when items are selectable, and add `aria-selected` to each option.

The `grid`, `row` and `gridcell` roles do not fit. A `grid` needs `row` elements that wrap their cells, and the grid renders no row elements. If you need to announce rows and columns, compute them with `getItemCell` and put the text in `aria-description`. Read it again on the `layout-change` event, because the column count changes when the grid is resized.
