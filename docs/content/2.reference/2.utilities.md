## `createPageProvider`

A helper function to create a `pageProvider` from a static array or a reactive reference. This is useful when you have the entire dataset locally and want to use the `<VirtualGrid>`'s pagination-based API.

### Type Definition

::field-group
  ::field{name="createPageProvider<T>" type="(data: MaybeRefOrGetter<T[]>) => (page: number, pageSize: number) => T[]"}
  Creates a pagination-based provider from an array or reactive data source.
  ::
::

### Usage

```ts
import { createPageProvider } from 'vvirtual-grid/vue'

const items = Array.from({ length: 1000 }, (_, i) => ({ id: i, title: `Item ${i}` }))

// Create the provider
const myPageProvider = createPageProvider(items)
```

::info
When using the Nuxt module, use `useVirtualGridProvider` instead as it is auto-imported
::

## Custom `pageProvider`

A `pageProvider` is an asynchronous function that tells the `<VirtualGrid>` how to fetch data for the grid based on the current page.

### Interface

::field-group
  ::field{name="PageProvider<T>" type="(page: number, pageSize: number) => T[] | Promise<T[]>"}
  The signature required for the `pageProvider` prop.
  ::

  ::field{name="page" type="number"}
  The current page index (starting from `0`).
  ::

  ::field{name="pageSize" type="number"}
  The number of items per page.
  ::
::

### Examples

#### Fetching from an API

This is the most common use case. You can fetch data from a backend service using `fetch` or `axios`.

```ts
const myPageProvider = async (page, pageSize) => {
  const response = await fetch(
    `https://api.example.com/items?offset=${page * pageSize}&limit=${pageSize}`
  )
  const data = await response.json()
  
  return data.items
}
```

#### Delaying page provider

If you want to simulate a slow network or avoid too many requests while scrolling fast, you can use the `pageProviderDebounceTime` prop on the `<VirtualGrid>` component.

### Best Practices

1. **Return correct length**: Ensure your provider returns up to `pageSize` items. If it's the last page, it can return fewer items.
2. **Handle errors**: Wrap your fetch logic in try/catch to prevent the grid from breaking on network failures.
